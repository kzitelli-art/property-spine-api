`POST /deal-setup/activations/:id/preview-source` parses the retained artifact server-side and returns grouped source identities, current hierarchy candidates, a source token, and scoped inventory fingerprints without changing leasing basis, inventory, import batches, source rows, or proposals. `read-source` now requires the preview token and an explicit existing/new/existing-parent decision for every current source home. Exact text is a suggestion. Prefix text is not matched. Retired, duplicate, unknown-grain, held-placeholder, and ambiguous-prior shapes remain explicit refusals or unresolved review.

The decision stays in the existing `proposed_records` history. Migration 196 adds only the durable joins JSON could not safely provide: `selected_unit_id`, `selected_space_id`, and `inventory_identity_decision_id`, all `ON DELETE RESTRICT`, plus completeness/ownership checks. The decision JSON retains the immutable artifact hash, raw and normalized source claim, leasing basis, review and confirmation fingerprints, selected hierarchy, action, and authority attribution. A lease proposal consumes that decision by foreign key. Its source labels are never rewritten to look canonical.

Apply locks the activation and serializes source review per property before inventory and authority locks. Authority is reread after every relevant wait and before the first operating write. The planner and apply share the same parser and decision resolver. Confirmation locks the approved target, rereads authority after the wait, and revalidates the decision's property, activation artifact hash, selected hierarchy, retirement state, and scoped fingerprint. It never resolves by label and has no missing-unit fallback.

Fresh rooms with one source parent materialize through the existing canonical materializer. Reviewed rooms under an existing parent use the same path: a pristine `(whole unit)` placeholder becomes the first room while retaining its ID, and held/mixed/surplus shapes refuse. The parent may be chosen explicitly even when retained source text `101` differs from canonical parent `1325-101`; raw `101` remains in source evidence. Exact repeated bytes may explicitly reuse the latest reviewed decision. A later explicit correction creates a new decision and evidence batch; an older decision cannot be revived.

Pre-196 staged lease claims are never back-labelled. The activation read names `source_home_review_required`; the app offers `restart-source-review`, which abandons only the old activation, retains its artifact, batch, source rows, and proposals unchanged, and opens a fresh review from the same bytes.
