## Governing build sequence

```text
canonical server truth
→ authenticated property-scoped projection
→ complete destination
→ home summary
→ honest empty and unavailable behavior

```

The home summarizes the operating system. It does not become a second operating system.

## Server responsibilities

The server owns lifecycle state, operating state, accountable owner, assignment state, due state, waiting party, blockers, primary action, record inclusion and exclusion, ordering, priority, economic truth, contractual truth, and cross-domain orchestration.

## Browser responsibilities

The browser may render server-authored fields, group by server-authored stage, display server labels, dispatch canonical navigation or named commands, preserve filters and return paths, and show honest nulls and unsupported states.

The browser may not infer lifecycle state, derive overdue status, invent ownership, choose a waiting party, create economic truth, reconstruct a lease schedule, rank cross-domain work, or substitute fixture data after a failed live read.

## Property scope

Every authenticated read and write derives property scope from the staff session. No client-selected property ID may authorize a live read or write.

## Counts

Home counts and destination counts must come from the same server projection. Do not create separate browser counts or alternate summary logic.
